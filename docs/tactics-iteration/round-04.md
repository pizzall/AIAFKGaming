# 第 4 轮：把否定、条件与站位做成「第二遍定位」

- 分支：`round-04-negation-and-layout`（从 `round-03-queue-and-targets` 出发）
- 代码：`src/battle/tactics.ts`（否定作用域改为结构化 `Negation`）、`src/battle/agent.ts`、
  `src/battle/layout.ts`（目标占位、替补避让）、`src/battle/plan.ts`（新增，第二遍定位：条件与例外）、
  `src/battle/view.ts`（占用位置反推）
- 测试：`tests/tactics.test.ts`（12 条）

## 本轮修掉了上一轮的什么

1. **否定作用域**：否定现在是一段「作用域」，覆盖到逗号或「然后/并/再」，`否则不要…` 吞到句末；
   一次否定可以吞掉多个动作（`Negation {text, actions[]}`），而不是只吞一个。
2. **读得到战局了**：`readView` 给出本方体力/状态/招式/攻击/速度、替补、已倒下，以及「被占用不能换入」的位置；
   对手仍然只通过日志确认倒下，请求里没有的对手信息一律不猜。
3. **条件拆成可判断的对象**：`plan.ts` 把「如果我方 1 号体力低于 50%」「对方体力低于 30%」等拆成 `Condition`，
   `evaluate` 只对本方可见信息求值；对手血量、对手只数、天气被标成「不可验证」而不是当成成立。
4. **目标占位**：同一回合的两只宝可梦不会选中同一只对手（`claimed`），队友被占时换另一只；
   第 1 轮「全员打 1 号」的问题在这一层修掉了「互相抢位置」，但还没修「按血量/速度挑人」。

## 本轮做得不够好的地方（测试逐条验证）

1. **条件不进决策**：`plan.conditions` / `plan.guarded` 只建了表，决策层还没有用条件决定出不出手，
   「如果我方 1 号体力低于 50%，使用守住」在满血时还是用守住。
2. **目标还不比较战况**：`lowestHp/fastest/threat` 只当作「对手」处理，没有对手的血量与速度可比较，
   「另一只对手」「前两个对手」也没有落到 2 号位。
3. **换人位置仍然错**：替换命令里用的是「替补下标」，引擎要的是「出战位」；多数种子会在替换时被拒绝，
   双倒时只补一个位置还会让引擎报「Not all choices done」。
4. **默认策略仍隐式**：战术无法消解时用请求里的第一招，可选招全被禁用时没有兜底；对手固定策略仍用同一套脚本。
5. **负向条件读不到**：「对方不会带守住」这类写法既不是「不要」类否定也不是条件词，整句被忽略，没有「无法验证」标记。

- `tsc --noEmit`：通过。

## 边界

- `plan.ts` 只做「第二遍定位」，不做第二次文本消解；它读的 `Condition` 只来自第一遍拆解出的条件片段。
- 对手信息边界：请求里没有对手队伍与招式，`view.foe` 永远为空；「已确认倒下」需要日志里的 `|faint|`，
  当前引擎适配层还没有把日志交给 agent，所以对手只数相关条件一律不可验证。
- 默认策略仍写死为「第一个可用招式」，没有做成可替换的 `DefaultPolicy`。
