# 第 5 轮：条件接进决策，对手信息只来自日志

- 分支：`round-05-conditions-and-opponents`（从 `round-04-negation-and-layout` 出发）
- 代码：`src/battle/plan.ts`（重写：条件、例外、负向判断、可验证性）、`src/battle/opponent.ts`（新增，事件累积的对手信息）、
  `src/battle/agent.ts`（条件驱动队列）、`src/battle/layout.ts`（显式默认策略）、`src/battle/runner.ts`（把上一回合本方事件交给 agent）
- 测试：`tests/tactics.test.ts`（12 条）

## 本轮修掉了上一轮的什么

1. **条件进决策**：「如果我方 1 号体力低于 50%，使用守住」满血时不再出守住，而是跳过这个动作、轮到队列里的下一个动作。
2. **可验证性明确**：对手血量、对手只数、天气这类请求里看不到的信息，标成 `unverifiable` 并进入 `ignored` 日志，
   不会被当成成立。
3. **负向条件有下落**：「对方不会带守住」现在被拆成 `claims`，标成 `foe-move` + `unverifiable`；
   对手是否真的会/不会，只能等日志里出现 `|move|p2…|Protect`。
4. **对手信息只从日志来**：`opponent.ts` 累积 `|move|p2…`、`|faint|p2…`、`|switch|p2…`；
   请求里没有对手队伍与招式，这是唯一合法的来源。
5. **显式默认策略**：`layout.defaultMove` 统一给「第一个可用招式 + 合法目标」，战术无法消解时不再散落在 agent 里。

## 本轮做得不够好的地方（测试逐条验证）

1. **目标不比较战况**：`lowestHp/fastest/threat` 只决定「打对手」，没法比较两只对手的血量与速度；
   「另一只对手」「前两个对手」也不落到 2 号位/两口位。
2. **换人位置没对齐**：替换命令仍然用「替补下标」，引擎要出战位；双倒只补一个位置会留下未完成的选择。
3. **默认策略不追问**：默认招式仍是请求里的第一招，没有把玩家的「没写」和「写了但没消解」分开记录。
4. **对手信息只能用一次**：`observe` 每回合只拿到「上一回合增量」，如果某回合没有请求（比如被替换打断），
   这段增量就丢了；也没有把「对手道具/特性」纳入。
5. **例外不执行**：`plan.exceptions` 只记录「除非 A 否则 B」，条件成立时并不会真的只执行 B。

## 测试结果

- `tests/tactics.test.ts`：12/12 通过（4 条历史回归 + 3 条条件/负向修复 + 5 条本轮目标）。
- 全量：61/61 通过（`base` 上本来就失败的 `game-gym` 用例也通过，原因是本轮在 runner 里加了事件交接后，
  引擎的随机序列与固定序列保持一致——这条需要在下一轮复核）。
- `tsc --noEmit`：通过。

## 边界

- `rebuildPlan` 只做「第二遍定位」，不再做第二次文本消解；条件片段来自第一遍拆解。
- 看不到的对手信息：请求里没有对手队伍、招式、道具、体力百分比；日志里只有本方可见的事件。
- 条件里的「对方」只能细化到「对手整体」，还没有「对方 1 号/2 号」的区分（日志事件里能区分，本轮没接）。
