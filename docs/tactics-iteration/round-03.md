# 第 3 轮：行动队列、目标站位与读取战局视角

- 分支：`round-03-queue-and-targets`（从 `round-02-scope-and-names` 出发）
- 代码：`src/battle/view.ts`（新增，只读本方请求）、`src/battle/layout.ts`（新增，目标/站位/替补）、
  `src/battle/agent.ts`（队列推进）、`src/battle/tactics.ts`（条件位置、否定词表）
- 测试：`tests/tactics.test.ts`（11 条）

## 本轮修掉了上一轮的什么

1. **队列不推进**：`1是X，2是Y` 现在用 round-robin 队列推进，每只宝可梦按自己的节奏轮换队列里的动作。
2. **不读战局**：新增 `readView`，只从 `request.side` / `request.active` 读本方体力、状态、招式、攻击与速度；
   对手信息在请求里本来就不存在（`view.foe` 永远为空），所以「看不到对方」变成一条明确的数据边界。
3. **目标只分会/不会**：目标词经 `layout.ts` 换算成站位 1/2；`self/allAdjacent*` 类招式不再被硬塞目标，
   单体招式一定带目标；队友招式（`adjacentAlly`）按引擎要求留空。

## 本轮做得不够好的地方（测试逐条验证）

1. **否定作用域**：「不要冒险」仍只吞掉后面第一个动作；「否则不要冒险」整句剩下的动作不会被吞。
2. **目标不比较战况**：没有比较对手的血量、速度、威胁，也没有「前两个对手」；被占用的对手站位才回退到另一只。
3. **换入位置不防 active 标记**：单只倒下且替补紧跟在倒下位置时，引擎直接拒绝换人（`drive()` 测试记录到这条错误）。
4. **默认策略是隐式的**：「试试」这类无法消解的文字没有显式默认策略；喷火龙会用「默认 1 号招式」而不是队列里的「守住」；
   可用招式全被禁用时会被引擎拒绝。
5. **负向条件读不到**：文本写「对方不会带守住」时，系统没有对手招式表可以验证，这句话既不是禁用也不是条件。

## 边界

- `readView` 不读取 `battle.p2`，也不从日志里推对手的招式；`view.foe` 固定为空，是「看不到对手」的显式边界。
- 队列在每只宝可梦第一次出场时从自己的一半位置开始，倒下/换人后清空，下一只上场重新认领。
- 走位 1/2 是引擎请求里的出战位，不是队伍编号；替补选择复用 `view.bench`（side.pokemon 顺序）。
