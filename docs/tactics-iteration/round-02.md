## 修掉了第 1 轮的什么

1. **条件遗漏**：例外/否定不再整句丢弃，「除非…否则」被拆成例外；但本轮例外仍只记录，不改排序（见下面第 1 条新不足）。
2. **否定误读**：「不要冒险使用喷射火焰」现在只吞掉紧挨着否定的「喷射火焰」，同一句里别的动作保留。
3. **目标词不执行**：目标词落到具体动作上（`lowestHp`、`fastest`、`foe`、`ally`），决策会用目标决定打 1 号还是 2 号位。
4. **优先级颠倒**：同句里换人整体后移，先出招、后换人；数字优先级逐条累加，不会两个动作抢同一个号。
5. **中文招式名无法消解**：新增 `src/battle/names.ts`，把 919 个 zh-hans 招式名、1025 个宝可梦名、英文名、内部 ID
   统一映射到引擎显示名；再叠加一张常用别称表（「保护/守住 → Protect」「加鲁克/水箭龟 → Blastoise」）。
   名字里夹了修饰时用 2–6 字滑动窗口取最长可消解片段（「保护主力」→「保护」）。

## 本轮做得不够好的地方（测试逐条验证）

1. **否定作用域太窄**：「不要冒险」只吞掉后面第一个动作；「否则不要冒险」整句剩下的动作不会被吞。
2. **行动队列不推进**：「1是X，2是Y」里两只宝可梦都从头认领队列，Y 永远轮不到（战斗里「守住」连用被引擎拒绝）。
3. **目标词不真找人**：`lowestHp/fastest/threat` 只决定站位 1/2，没有比较对手的血量、速度、威胁；队友之间的站位更不判断。
4. **换人不主动**：「换上」只会在倒下后的替换请求里用；主回合不会主动换人，也不按速度/体力选人。
5. **名字消解边界**：招式名前写「喷火龙的地震」仍被解析成上下场；队友站位（「守住队友」）仍按 2 号位出，会被引擎拒绝。
