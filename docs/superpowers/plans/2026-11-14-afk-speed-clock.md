# 挂机变速齿轮与统一游戏时钟

用户授权：测试指令页面增加1–1000倍变速齿轮，2倍意味着全部AFK速度翻倍；时间计算集中在后端统一接口，禁止各判断分散乘倍率。沿用当前测试工具的账号范围。

## 实施边界

- 新增 `src/game/clock.ts`：GameClock 负责真实时间提供、个人游戏时间读取、倍率切换检查点、手动推进和现实剩余时长换算。倍率切换先保留已累积游戏时间，禁止对过去整段时间重算。GameService不再手写 realNow + clockOffset。
- `types.ts`：复用clockOffset作为锚点时的游戏/现实偏移，只新增可选clockRate与clockAnchorRealAt两个标量。旧存档缺省1倍，保留已有偏移、游标与截止时间，不新增DB表。
- `service.ts`：探索、产业、果园、产蛋/孵化、恢复、商店及个人日志共用GameClock；时间仍以游戏毫秒保存。测试命令设置倍率（1–1000整数），先按旧倍率做一个已有的有界补结算批次；倍率命令允许在catchingUp时执行，不要求清空欠账才能恢复1倍，原游标和累计游戏时间保留。普通模式拒绝设置，启动时以同一真实时间将历史测试倍率归1，保留截至启动的游戏进度。
- `store.ts`：会话有效期明确使用真实时间源，不读取玩家倍率或偏移。真实审计/全服比赛不改为个人挂机时钟。
- `web/game/app.js/styles.css`：测试页倍率输入与快捷档、恢复1倍、当前速率提示；所有倒计时以同一个服务端游戏时间快照/倍率推算现实剩余时间，界面推算不发奖。倍速下有挂机活动时适度轮询，输入草稿不被刷新覆盖。用户操作可让连续补结算在当前请求完成后暂停，再提交倍率命令；输入框聚焦时被动刷新不替换表单。
- 新增 `tests/game-clock.test.ts`：倍率连续性、手动推进、边界/账号隔离/普通模式关闭、重启持久化、多个AFK模块同速与会话不加速。
- README/架构记录统一时钟入口与用法；保持本机测试服务。

## 实施与验证记录

新增纯时钟和5项业务测试，先观察缺失时钟模块导致失败，再接入实现。全量37项测试通过，`tsc --noEmit`与前端语法检查通过。覆盖2倍1现实小时/1倍2小时多模块等价、按倍率恢复、非法档位、账户隔离、重启和离线持久化、原存档偏移兼容、普通模式启动恢复1倍、会话不加速，以及欠账期间降速。

比例设计审查发现：若倍率命令沿用其他命令的“先清空全部欠账”限制，高倍率下可能无法恢复1倍。已允许倍率命令在有界结算后直接执行；前端持续刷新也会让出用户操作，保留倍率表单和草稿。相同审查复核未留下Important项。

浏览器实测2倍与1000倍的游戏/现实时间斜率分别为2和1000，产业及果园跟随推进。自动刷新时倍率草稿、指令草稿和输入焦点不丢失；模拟持续补结算时无需清空欠账即可恢复1倍，后端真实欠账场景另由测试覆盖。1920×1080与390×844均无横向溢出，浏览器控制台无错误。截图：`.runtime/ui-speed-clock.png`。测试账号最终恢复1倍，保持原探索状态不变。
