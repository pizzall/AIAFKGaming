# 宝可梦挂机游戏数据与数值总表

版本：0.1；日期：2026-11-13；状态：与 [需求与模块设计](game-design.md) 配套的参数账本。

本表集中记录当前讨论中的全部明确数字、用户示例、候选公式、待定数值和模块内容表字段。它不冒充已经完成的全物种图鉴、全部招式库或最终平衡配置。基础机制已收敛为第九世代＋Mega；具体内容版本、首批范围和掉率尚未决定，因此未有依据的值明确写为“待定”，不能在实现时把它解释为零。

基础资料与图片另存于 [宝可梦数据快照](../data/README.md)，包含上游全物种、形态、招式等原始表以及大立绘和像素精灵图；采集这些资料不表示已选定本作的规则世代、开放范围或平衡参数。

道具与树果原始资料的数量、中文覆盖、字段缺失和图片缺口见 [专项核查](item-berry-coverage.md)；其上游字段与 Demo 价格样例均不替代本表的正式参数。

规则状态沿用主文档：已确认、建议基线、示例、推导、待定、暂缓。公式中的演算数据仅用于解释和验证性质，不等于游戏实际产出。

## 1 数据维护约定

1. 参数变更至少记录旧值、新值、状态、理由与生效范围；确认需求与平衡初值不得混为一类。
2. 服务器事件时间统一保存为绝对时间；每日时间窗按配置时区解释。建议测试服采用 Asia/Shanghai。
3. 概率统一使用 0–1，展示时可转为百分比；权重是非负相对值，不能直接作为概率。
4. 时长在运行配置中统一使用秒；本文可同时列分钟、小时和天。一日按 24 小时计算，不代表必须每 24 小时领取一次。
5. 金钱、物品数量、等级、个体值、努力值等使用整数；公式中的连续收益允许保留余数，不能靠频繁领取重复取整增益。
6. “无上限”“禁用”“待定”“零”分别表达，不互相替代。待定的关键配置不得静默投入正式测试。
7. 对外公开的物种和道具采用统一中文名称与稳定标识；昵称不作为物种或个体的唯一标识。
8. 配置分为运行时生效与批次冻结生效。孵化批次和已报名比赛继续使用各自冻结版本，不追溯套用新参数。

## 3 数值基础建议

下表作为保留传统个体培养体系的建议基础，尚不等于选定完整世代。战斗招式、特性、特殊机制和内容版本仍需 Q01 决策。

| 参数 | 建议值 | 状态 | 约束 |
| --- | --- | --- | --- |
| minimum_level | 1 | 建议基线 | 孵化初始等级单独配置 |
| maximum_level | 100 | 已确认目标 | 不默认加入等级突破 |
| stat_count | 6 | 建议基线 | HP、攻击、防御、特攻、特防、速度 |
| iv_min / iv_max | 0 / 31 | 建议基线 | 各项整数 |
| ev_stat_max | 252 | 建议基线 | 单项努力值 |
| ev_total_max | 510 | 建议基线 | 总量不超过该值 |
| equipped_move_slots | 4 | 建议基线 | 学习记录容量与装备招式位分开 |
| held_item_slots | 1 | 建议基线 | 道具允许持有且实际归属合法 |
| nature_positive_multiplier | 1.1 | 建议基线 | 对应性格的受益属性 |
| nature_negative_multiplier | 0.9 | 建议基线 | 对应性格的受损属性 |
| nature_neutral_multiplier | 1.0 | 建议基线 | 其他属性，HP 不使用性格乘区 |

传统数值体系的单项属性公式与特殊物种例外可参考 [Stat 机制资料](https://bulbapedia.bulbagarden.net/wiki/Stat)；努力值上限可参考 [Effort values 机制资料](https://bulbapedia.bulbagarden.net/wiki/Effort_values)；性格乘区可参考 [Nature 机制资料](https://bulbapedia.bulbagarden.net/wiki/Nature)。这些是机制参考，不为本作新增的捕获、继承或经营规则背书。

设 B 为种族值、I 为个体值、E 为努力值、L 为等级、N 为对应性格乘数，floor 为向下取整，建议采用：

```text
HP = floor((2 × B + I + floor(E / 4)) × L / 100) + L + 10
其他属性 = floor((floor((2 × B + I + floor(E / 4)) × L / 100) + 5) × N)
```

特殊物种的固定 HP 等规则由基础数据覆盖，不在公式外随意增加补偿。招式伤害、命中、行动顺序、天气场地和特性联动必须整体遵守同一个规则版本，本表不把一个简化伤害表达式当作完整对战规则。

## 4 经验目标与校准公式

### 4.1 参考曲线

先用中速成长曲线 E(L) = L³ 作为计算参考，L = 1 时总经验按 0 处理。该曲线及原作不同成长组可参考 [Experience 机制资料](https://bulbapedia.bulbagarden.net/wiki/Experience)。本作是否所有物种统一使用这条曲线仍待定。

| 项目 | 计算值 | 用途 |
| --- | --- | --- |
| E(5) | 125 | 参考起始累计经验 |
| E(100) | 1,000,000 | 参考满级累计经验 |
| 5→100 所需经验 ΔE | 999,875 | 两者之差 |
| 7 天个人平均净经验 | 约 5,951.64 /小时 | 999,875 ÷ 168 |
| 8 天个人平均净经验 | 约 5,207.68 /小时 | 999,875 ÷ 192 |
| 8.5 天个人平均净经验 | 约 4,901.35 /小时 | 999,875 ÷ 204 |
| 9 天个人平均净经验 | 约 4,629.05 /小时 | 999,875 ÷ 216 |
| 六只共同成长的总经验需求 | 5,999,250 | 6 × 999,875，仅用于核算 |
| 六只在 8–9 天完成的合计平均净经验 | 约 27,774.31–31,246.09 /小时 | 是整队总量，不是每只的速率 |

这里的平均净经验按整个参考时段计算，不能直接成为每个地区、每个等级恒定的每小时奖励。不同成长曲线若保留，需要分别验证是否仍满足目标范围。

### 4.2 分配候选式

```text
成员经验 = 遭遇经验基数 × 参与或学习系数 × 等级补偿系数 × 合法增益系数
```

候选式对每名合法探索队成员分别计算，不把一个单只经验池机械均分六份。长期统计需要同时约束个人与整队总产出。

| 参数 | 当前值 | 状态 | 约束与用途 |
| --- | --- | --- | --- |
| encounter_xp_base | 待定 | 待定 | 按地区、敌人及难度给出，不由纯等级差无限放大 |
| active_member_xp_factor | 1.0 | 建议基线 | 作为其他系数的比较基准 |
| learning_device_xp_factor | 待定 | 待定 | 要能支持整队约 8–9 天，不默认等于原作数值 |
| low_level_bonus_function | 待定 | 待定 | 等级差补偿函数，必须有有限上限 |
| low_level_bonus_max | 待定 | 待定 | 防止成熟成员带新形成极端速度 |
| overlevel_reward_factor | 待定 | 待定 | 处理长期刷过低等级地区的效率 |
| cap_level_xp_redistribution | 不自动转移 | 建议基线 | 满级成员溢出经验不全部灌给替补 |
| xp_fraction_handling | 保留余数 | 建议基线 | 分次领取不改变长期经验 |

定义利用率 u = 实际净经验速率 / 参考满负荷经验速率，简化关系为 T_actual = T_reference / u。以 7 天为参照，8 天对应 u = 87.5%，9 天对应 u ≈ 77.78%。这只是解释探索缺口与恢复损失的诊断量，不应再作为额外扣减乘数叠加到已经扣除恢复时间的结算中。

完整经过某段时间时：有效探索时间 + 恢复时间 + 其他明确停机时间 = 该段总时长。若期末仍在恢复，只计算本段实际重叠时间，并保留剩余恢复时长。

示例：8 小时内累计发生完整的 80 分钟恢复，则剩余有效探索时间为 400 分钟，即 6 小时 40 分钟。不能再在这 400 分钟的结果上额外乘一次“恢复损失比例”。

日常配置变更必须先结算旧状态；产出或随机结果按事件生成后固定。用同一事件随机序列检查一次领取与分次领取的等价性。

## 10 产业与经济参数

### 10.1 产出候选式

设 C 为当前设施级别允许的每小时产能上界，e 为在岗成员综合效率且 0 ≤ e ≤ 1，N 为分配给该设施的后备成员数，β ≥ 0 为后备增益幅度参数，K > 0 为递减速度参数：

```text
R = C × e × (1 + β × (1 - exp(-N / K))) / (1 + β)
```

该候选式在固定 C 与 e 时随 N 增大而增加、边际收益递减，且不超过 C × e。没有在岗成员时 e = 0，不能只靠后备成员空转。后备成员被该设施占用，不同时计入别的设施或探索。

演算示例取 C = 100 单位/小时、e = 1、β = 0.5、K = 10：

| 后备数量 N | 每小时产量 R | 数据性质 |
| --- | --- | --- |
| 0 | 约 66.67 | 公式演算 |
| 10 | 约 87.74 | 公式演算 |
| 20 | 约 95.49 | 公式演算 |
| 趋近无限 | 趋近 100 | 仅用于说明固定设施产量上界 |

以上不是矿山或木场的实际初值。扩建会改变 C 或增加设施，因此账户总收入仍需要结合可建数量、设施等级、成本和资源消耗验证，不能把单设施有界当成全经济已经平衡。

### 12.2 概率解释与校准

对于独立且同概率的 n 次机会，每次成功率 p：

```text
至少成功一次的概率 = 1 - (1 - p)^n
首次成功的平均机会数 = 1 / p
```

示例 p = 0.001、n = 1000 时，至少成功一次约为 63.23%，不是必然获得。此例不规定任何物品的真实掉率。

多层获取链应使用条件概率核算：遇到目标的概率 × 遇到后捕获成功概率 × 捕获后满足培养目标的条件概率。不能只看单独某一层觉得“掉率不算低”。具体概率依物种、球、时段和培养目标共同确定。

稀有掉落的验证同时报告平均、分位数和未获得比例；所有保底、自选或兑换渠道都必须单独写入数据，不在体验承诺中隐含。
